## Red test root cause

The required no-GPU lifecycle test initially reproduced intermittently. Classification: **C — race/timing/state synchronization in the test fixture**. The fixture started the real background production queue runner, then manually wrote successful batch/task/asset truth. The runner could still write its Comfy failure state after the manual lineage write, so the selection query no longer saw the expected three generated image assets.

## Red test fix

The fixture now uses a non-completing Comfy event subscription and synchronizes on the persisted batch-item state leaving `PENDING`/`DISPATCHING` before writing its deterministic no-GPU truth. This preserves the original lineage and ordering assertions and removes the fixed sleep. No production execution path, assertion, ignore, or timeout workaround was changed.

Required test, repeated five times:

`production_run_lifecycle_keeps_batch_task_asset_lineage_without_gpu`: **5/5 PASS**.

## Production Audit architecture

`ProductionAuditService` is a read-only aggregate over the existing SQLite model. It adds no migration, table, event-sourcing stream, second task history service, queue, generation system, or shot system. Existing run, stage, batch, task, snapshot, asset, shot, and generation-link tables are loaded with set-based queries and joined in memory.

Registered commands:

- `production_audit_summary`
- `production_audit_recent_activity`
- `production_audit_lineage`
- `production_audit_integrity`

## Task History reuse

`ProductionAuditCenter` is a tab inside the existing Task History workspace. It is not a new top-level application. Task navigation returns to the existing `TaskHistory` and `TaskHistoryDetail`; Shot links return to the existing Shot workspace.

## Audit summary

Summary includes project identity, active/completed/failed runs, active/paused/failed batches, logical items, attempts, succeeded/failed/review-required items, task totals and terminal task totals, asset totals, unassigned shots, check time, issue list, and `HEALTHY`/`WARNING`/`BLOCKED` health.

## Recent activity

Recent activity is derived from existing creation, update, completion, retry, task, asset, and Shot-selection timestamps. The default limit is 50 and the hard maximum is 200. The UI provides all/failed/running/retried filters, keyword filtering, task navigation, Shot navigation, and lineage inspection.

## Lineage

The lineage command supports `RUN`, `BATCH`, `SHOT`, and `TASK` roots. It returns an ordered, parent-linked tree surface covering Run → Stage → Batch → logical item/attempt → Task → Snapshot → Asset, with Shot generation links and integrity issues included where applicable.

## Integrity checks

The audit detects missing stage/batch task references, missing task-output asset mappings, missing Shot generation-link task or batch-item references, missing selected Shot assets, and retry missing-parent, duplicate-child, and cycle/no-root corruption. Legal pending Shot links and legal failed/review states are not treated as structural corruption.

## No-GPU audit E2E

The backend fixture covers three logical Shots/items: A succeeds, B fails then B2 succeeds, and C fails without retry. Summary distinguishes logical items from attempts and resolved/failed leaves; recent activity contains B → B2 retry activity; all four lineage roots are exercised; healthy/review data is not `BLOCKED`; a corrupt retry-parent fixture is `BLOCKED`.
