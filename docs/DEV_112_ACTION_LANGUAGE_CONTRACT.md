# DEV-112 — Action Language Contract

**状态：** COMPLETE
**范围：** 生产入口、准备、返工、审核和失败反馈的可见动作文案。

## 1. 动作总表

| 动作 | 用户可见文案 | 真实效果 | 明确不做什么 |
| --- | --- | --- | --- |
| Queue Start | **开始生产** | 调用现有 Production Queue Start，提交真实生产并进入运行反馈 | 不只是保存、下一步或导航 |
| Resume paused queue | **继续生产** | 恢复现有队列的执行 | 不创建第二个队列 |
| Prepare | **准备场景生产** / **创建待启动批次** | 预检并创建 `READY`/“待启动”批次或项目 | 不提交生成任务、不启动队列 |
| Rework preparation | **编辑返工准备** / **创建返工批次** | 创建新的“待启动”返工批次，保留原失败/审核记录 | 不立即重新生成、不写成“重新运行” |
| Review selection | **选择结果并通过** / **已选择结果** | 写入明确的候选选择和审核通过事实 | 不代表发布 |
| Retry failed item | **创建重试项** | 创建新的执行尝试，原失败记录保留 | 不覆盖原失败记录 |
| Partial resume | **恢复并开始选中项** | 创建新的恢复项目并按现有恢复路径尝试开始生产 | 不把恢复准备伪装成已完成；启动失败须单独反馈 |
| Review rejection | **审核拒绝** | 写入审核拒绝事实 | 不使用“废弃”混淆业务含义 |
| Cancel pending queue | **取消待启动** | 取消尚未提交的项目 | 不影响已经提交的任务和资产 |

## 2. 入口语义

### 开始生产

所有审核过的队列入口都使用“开始生产”或“继续生产”。按钮、aria label 和成功反馈都必须让用户知道这是**真实生产开始**：

> 生产已启动，任务正在运行；可打开生产监控查看进度。

点击前的“待启动”不能显示为“处理中/运行中/生成中”。点击成功后，队列/任务使用“运行中”。

### 准备

准备页的成功反馈必须同时说明两件事：批次已经创建、真实生产尚未开始。例如：

> 已创建待启动批次和项目；当前尚未开始生产，也没有提交生成。

生产包快速创建、场景准备和项目级准备都复用现有 Queue/Store 路径；打开队列是导航，只有队列中的“开始生产”才是生产闸门。

### 返工

返工提交后的反馈必须包含“返工批次已创建”“状态为待启动”“尚未开始真实生产”，并指向队列中的“开始生产”。原批次、原任务和原失败事实保留。

## 3. 审核动作

- A/B 比较只改变比较槽位，不选择 Shot。
- “选择结果并通过”会先写入选择事实，再写入审核通过；如果选择写入失败，不继续写审核状态。
- 成功反馈使用“已选择结果”，不用“最终结果”“最终视频”或“发布结果”。
- Review Inbox 的“已选择结果”是素材导航，不是发布 CTA。

## 4. Loading / error / completion

- Loading 文案描述正在做的动作，如“正在创建待启动批次…”、“正在开始生产…”，不使用模糊的“处理中”。
- 失败文案使用“失败，需要处理”，并提供错误详情、重试或重新准备入口。
- 失败批次可以保留“查看已完成成品”（如果确有成功输出），但隐藏“打开成品文件夹”“导出成品清单”“选择下一个生产包”等只适用于完全成功的动作。
- 重试/恢复反馈要说明是否已经调用 Start；恢复路径是“恢复并开始”，返工路径只创建待启动批次。

## 5. 技术细节的展示位置

业务名称、场景名、镜头名、批次名和素材名是第一视觉。精确的 `workflowVersionId + recipeId`、`batchId`、`itemId`、`taskId` 和 `assetId` 可在详情、辅助文本、审计或 inspector 中查看，且始终使用当前项目范围。

## 6. 非目标

动作合同只改展示语言和反馈，不新增队列/执行器/任务/审核模型，不改变 Studio Store 或 Production Queue authority，不改变 IPC、Rust persistence、schema 或迁移。
