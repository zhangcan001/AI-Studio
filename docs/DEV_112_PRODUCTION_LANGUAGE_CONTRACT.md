# DEV-112 — Production Language Contract

**状态：** COMPLETE
**适用版本：** AI Studio 1.3 first theme
**范围：** 用户可见的生产状态、审核状态和状态说明。协议值、数据库枚举和领域归属不变。

## 1. 核心原则

1. **状态描述事实，不描述用户下一步猜测。** `READY` 只说明准备已完成；只有明确开始后才进入 `RUNNING`。
2. **准备和执行分开。** 预检、准备、创建批次、创建返工批次都不能被文案描述为已经生成。
3. **完成不等于选中或发布。** `COMPLETED` 只表示执行完成且存在结果；选中结果和发布是独立的后续事实。
4. **失败必须可处理。** 失败提示要说明需要处理，并保留查看错误、重试或查看已完成结果的准确入口。
5. **业务名称优先。** 名称、镜头名、批次名或素材名先出现；`batchId`、`itemId`、`taskId`、`assetId` 和 workflow/recipe pair 放在详情或辅助信息中。

## 2. 状态词典

### 2.1 生产批次 / 队列

| 协议状态 | 首选展示 | 含义 | 禁止暗示 |
| --- | --- | --- | --- |
| `READY` | **待启动** | 准备、准入和批次创建已完成，但尚未执行生产 | 处理中、运行中、生成中 |
| `RUNNING` | **运行中** | Queue Start 已被调用，执行正在进行 | 待启动、已完成 |
| `PAUSED` | **已暂停** | 队列被明确暂停，未提交项等待后续操作 | 已失败、已完成 |
| `COMPLETED` | **已完成** | 执行完成且有可查看的结果 | 已选择、最终结果、已发布 |
| 失败事实 | **失败，需要处理** | 执行失败，需要查看错误或创建新的执行尝试 | 异常完成、成功完成 |

批次 type 当前没有新增失败枚举；失败可由现有批次/项目事实派生。此合同只规范展示层，不扩展数据库状态。

### 2.2 批次项目 / 任务

| 协议状态 | 首选展示 | 说明 |
| --- | --- | --- |
| `PENDING` | **待执行** | 已进入批次，但还没有提交为运行任务 |
| `DISPATCHING` | **正在提交** | 正在将项目提交到执行端 |
| `DISPATCHED` / active task | **运行中** | 已提交并正在执行 |
| `SUCCEEDED` | **已完成** | 本项目有执行结果；不自动表示已选或已发布 |
| `FAILED` | **失败，需要处理** | 失败记录保留；重试会创建新的尝试 |
| `CANCELLED` | **已取消** | 本项目不再执行 |
| `SKIPPED` | **已跳过** | 明确跳过本项目 |

### 2.3 审核与结果

| 审核事实 | 首选展示 |
| --- | --- |
| `UNREVIEWED` | **待审核** |
| `APPROVED` | **已通过** |
| `STARRED` | **已标星** |
| `REGENERATE` | **待返工** |
| `REJECTED` | **已拒绝** |
| `FAILED` | **失败，需要处理** |
| `IN_PROGRESS` | **运行中** |

审核通过仍不等于发布。只有存在明确的发布事实时，才可以使用“已发布”等词。

## 3. 上下文边界

- **场景准备页的 `READY` 候选**表示上下文检查通过、允许进入准备动作，用户界面展示为“可准备”；创建后产生的 Production Batch 才展示为“待启动”。这避免把“可准备镜头”误认为已经在运行。
- **外部 Production Package 的 `READY/WARNING/BLOCKED`**是包检查协议值。它们在兼容性/协议详情中可以保留原值；它们不代表 Production Queue 的批次状态。
- **Shot 流程**使用“待启动”“运行中”“待审核”“已选择关键帧/视频候选”等词区分执行阶段和审核阶段。

## 4. 结果与素材

- “已完成”只说明存在执行结果。
- “已选择结果”只说明 Shot/审核事实已经选择了某个候选；它不是“最终视频”或“已发布”。
- Asset Library 的分类（源图片、生成图片、源视频、生成视频等）描述素材来源，不推断审核选择或发布状态。

## 5. 非目标

本合同没有新增状态机、队列、任务、审核或素材模型，没有修改 Rust、SQLite schema、迁移或 DB 枚举，也没有引入新的组件框架或设计系统。
