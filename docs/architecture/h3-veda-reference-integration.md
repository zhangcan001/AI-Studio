# MiniMax H3 Veda reference generator

- Package: `minimax_h3_reference_veda_turbo_1_0_0`; workflow `wfl_minimax_h3_reference_veda_turbo` + Recipe `rcp_minimax_h3_reference_veda_turbo_1_0_0`, version1.0.0.
- Source: user-supplied API workflow `Veda 加速全能参考.json`. Default enabled branch is Turbo LoRA4steps followed by VedaSparseAttention before BasicGuider. Original standard20step generator and all historical runtime-package files remain unchanged.
- Product supports1–8 explicitly ordered reference images. Slots are independently bound; omitted image loaders/links are removed by the existing compiler. Zero or9 images are invalid. No reference video/audio slots are advertised for this image-only variant.
- Prompt, width/height, duration4–15seconds, seed and ordered image assets use the existing Recipe compiler and Queue. Default5seconds,1376×768 (existing1.0MP product preset),24fps; existing standard-reference video/audio trim nodes keep delivered duration aligned to the user request.
- Uploaded source examples/private filenames and prompt are not embedded. Five empty image loader slots extend the original three, without changing model/predictor filenames, Turbo LoRA strength, sampling algorithm or Veda sparsity32.
- Required external node: `VedaSparseAttention`; predictor `minimax_h3_r2va_veda_preview_fp8.safetensors`. The LoRA, UNet, CLIP and VAEs retain the source workflow's exact filenames. Availability is checked through the existing formal runtime preflight; this change never downloads models, installs custom nodes or submits a prompt.
- Discovery/provenance: searched the upstream implementation and reused the local immutable-package/compiler mechanisms. [Veda upstream](https://github.com/veda-sparse/Veda-on-ComfyUI) is MIT-licensed; its executable implementation is not copied or bundled. [Official ComfyUI H3 node contract](https://github.com/Comfy-Org/ComfyUI/blob/master/comfy_extras/nodes_minimax_h3.py) documents ordered reference inputs. No extra library or executor was introduced.
- New package is additive and does not automatically replace the project's chosen/default generator. MiniMax video authorization stays pinned to the explicit package, exact WorkflowVersion+Recipe and immutable/live bytes. Scheduling remains GPU-heavy and serial, max1.
- Native/GPU generation is not implied by compiler/registry tests. Acceleration and output quality require a separately authorized real generation test.
